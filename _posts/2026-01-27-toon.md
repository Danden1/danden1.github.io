Recently, I’ve been developing AI agents at my company.

I’m very interested in AI, and I genuinely enjoy working with it. Building a simple AI agent is quite straightforward—you can get started quickly by following the LangChain documentation.

However, my goal is to build AI agents that can be used by many users and are commercially viable.

As you know, large language models (LLMs) are expensive to run. In particular, AI agents need to manage context—such as conversation history and user preferences—to improve accuracy. This often leads to a significant increase in token usage and, ultimately, cost.

Because of this, I started researching ways to reduce token usage in AI agents.

## Token-Oriented Object Notation (TOON)

In general, structured output is cheaper than unstructured text.

At first, I used the JSON format. However, JSON is relatively expensive in terms of token usage.

```json
{
    "data": [
        {
            "id": 1,
            "email": "test@test.test",
            "gender": "male",
            "phone": "12345678"
        },
        {
            "id": 2,
            "email": "test2@test.test",
            "gender": "female",
            "phone": "12345679"
        }
    ]
}
```

JSON contains duplicated field names and a lot of structural characters, such as braces and commas.

TOON takes a different approach.

```yaml
data[2]{id,email,gender,phone}:
  1,test@test.test,male,12345678
  2,test2@test.test,female,12345679
```


It’s much simpler.

Compared to JSON, this format uses about 33% fewer tokens.

_source: [TOON github](https://github.com/toon-format/toon)_

### Real-World Example

While researching Agentic Context Engineering (ACE) ([my previous post](https://danden1.github.io/posts/ai-agent-ace/)), I noticed that it already uses TOON.

Here is an example from the ACE codebase:
```python
def as_prompt(self) -> str:
    """
    Return TOON-encoded skillbook for LLM prompts.

    Uses tab delimiters and excludes internal metadata (created_at, updated_at)
    for maximum token efficiency (~16-62% savings vs markdown).

    Returns:
            TOON-formatted string with skills array

    Raises:
            ImportError: If python-toon is not installed
    """
    try:
        from toon import encode
    except ImportError:
        raise ImportError(
            "TOON compression requires python-toon. "
            "Install with: pip install python-toon>=0.1.0"
        )

    # Only include LLM-relevant fields (exclude created_at, updated_at)
    skills_data = [s.to_llm_dict() for s in self.skills()]

    # Use tab delimiter for 5-10% better compression than comma
    return encode({"skills": skills_data}, {"delimiter": "\t"})
```
_source: [ACE github](https://github.com/kayba-ai/agentic-context-engine)_


ACE officially introduced TOON in its release notes as well: [Release Note](https://github.com/kayba-ai/agentic-context-engine/releases/tag/v0.5.0)

## Conclusion

This experience made me realize that data formats are more important than I initially thought.

In our company servers, switching from JSON to Protobuf significantly improved performance. I already knew that data formats matter for server efficiency, but this work reminded me that they are equally important for reducing AI agent token costs.

By continuously exploring these seemingly small optimizations(?) and keeping up with new research, I plan to gradually reduce overall costs while building more scalable AI agents.
