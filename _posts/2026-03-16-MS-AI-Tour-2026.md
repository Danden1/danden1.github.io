am developing AI agents at a company.

I participated in the MS AI Tour Agenthon 2026 in Seoul.

This event was a month-long hackathon with the topic: “Workflow automation using AI agents.”

## Why I Participated

I was curious how other companies use AI agents for workflow automation.

I wanted to learn about the pitfalls and best practices when developing agents.

I participated together with a colleague from my company.

As a result, our team was selected as one of the Top 10 teams, and we were invited to present our project.

## Our Team’s Outcome

We developed an agent designed to streamline workplace communication.

## Existing Problems

After arriving at work, employees need to check messengers (email, Teams, etc.) and manually create a to-do list for the day.

Developers must create development tickets based on planning tickets, then write prompts based on those tickets, review them, and finally open a PR.

We found this workflow cumbersome.

## Our Agent

When a user says “Summarize my tasks” after arriving at work, the agent analyzes messenger content and generates a to-do list for the day.

When a planning ticket is provided, the agent generates a development ticket and proceeds to create a PR. After human review, once GitHub Copilot is enabled, development continues using prompts tailored to the project.

Development artifacts are stored in AI Search (MS Vector DB) to manage history. This makes it easy to check service history or quickly determine whether a feature already exists.

In this way, we aimed to reduce the communication overhead involved in daily work. In particular, managing service history is tedious.

## What I Learned

I learned how to use Microsoft’s Agent Framework (MAF).

If you are working in an Azure environment, this framework could be a good option.

Although we did not make it into the Top 3, the experience was highly valuable.

Technically, many aspects were already familiar to me, but the event helped me understand what kinds of problems are worth solving with agents.

The Top 3 teams focused not on automating development workflows, but on automating tasks that directly impact customers or can be used across teams.

For example:

Reviewing server architecture for security risks

Detecting boiler malfunctions in advance and recommending which repair tools to bring, while notifying the technician

Generating presentation scripts from uploaded slides, then analyzing the presenter’s tone and speaking speed from a recording

This made me think that developing domain-specific agents might be more effective.

At my company, we had previously developed an agent for automated ticket processing and initially planned to use it for this hackathon. We also applied Agent Context Engineering, but we could not continue due to infrastructure limitations. I plan to refine this further in the future.
