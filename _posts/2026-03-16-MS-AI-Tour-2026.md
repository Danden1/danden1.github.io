I am developing AI agents at my company.

I participated in the MS AI Tour Agenthon 2026 in Seoul.

This event was a month-long hackathon with the theme “Workflow automation using AI agents.”

## Why I Participated

I was curious about how other companies use AI agents for workflow automation.

I wanted to learn about the pitfalls and best practices when developing agents.

I participated with a colleague from my company.

As a result, our team was selected as one of the top 10 teams, and we were invited to present our project.

## Our Team’s Outcome

We developed an agent designed to streamline workplace communication.

## Existing Problems

After arriving at work, employees need to check messaging apps (email, Teams, etc.) and manually create a to-do list for the day.

Developers must create development tickets based on planning tickets, then write prompts based on those tickets, review them, and finally open a PR.

We found this workflow cumbersome.

## Our Agent

When a user says “Summarize my tasks” after arriving at work, the agent analyzes messenger content and generates a to-do list for the day.

When given a planning ticket, the agent creates a development ticket and drafts a prompt. After a person reviews the prompt, GitHub Copilot uses it to continue development and prepare a PR.

Development artifacts are stored in Azure AI Search to maintain a record of past work. This makes it easy to review the service history or quickly determine whether a feature already exists.

Our goal was to reduce the communication overhead in daily work, especially the tedious work of maintaining a service history.

## What I Learned

I learned how to use Microsoft’s Agent Framework (MAF).

If you are working in an Azure environment, this framework could be a good option.

Although we did not make it into the top three, I still learned a lot from the event.

Technically, many aspects were already familiar to me, but the event helped me understand what kinds of problems are worth solving with agents.

The top three teams focused not on automating development workflows, but on automating tasks that directly affect customers or can be used across teams.

For example:

- Reviewing server architecture for security risks
- Detecting boiler malfunctions in advance, recommending which repair tools to bring, and notifying the technician
- Generating presentation scripts from uploaded slides, then analyzing the presenter’s tone and speaking speed from a recording

This made me think that developing domain-specific agents might be more effective.

At my company, we had previously developed an agent for automated ticket processing and initially planned to use it for this hackathon. We also applied Agentic Context Engineering, but we could not continue because of infrastructure limitations. I would like to revisit this work when the infrastructure allows it.
